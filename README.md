# AstrBot B站监控助手

监控 B 站 UP 主的**动态 / 视频 / 专栏 / 音频 / 转发**，以及**直播开播与下播**，命中后主动推送到指定的 QQ 群或私聊。

移植自萌Q（MQNT）框架的插件 `bili监控助手.dll`，按 AstrBot v4 的插件规范重写：配置进 WebUI、订阅拆成三个列表、额外带一个可视化仪表盘。

插件目前没有上架Astrbot插件市场，仅能通过下载zip导入或者git安装

## 功能

| 能力 | 说明 |
|---|---|
| 新动态 | 图文、纯文字、opus 卡片 |
| 新视频 | 从 `MAJOR_TYPE_ARCHIVE` 或 opus 视频卡提取标题、封面、链接 |
| 新专栏 | `MAJOR_TYPE_ARTICLE`，也认 opus 里的 `/read/` 链接 |
| 新音频 | `MAJOR_TYPE_AUDIO` |
| 转发动态 | 带上原动态作者与内容 |
| 开播提醒 | 带直播标题、封面、直播间链接，可 @全体 |
| 下播提醒 | 带直播时长与人气峰值 |
| **推送隔离** | 每个 UP 主只推自己配的群，多群也行，互不串台 |
| **扫码登录** | 仪表盘按钮或 `/bili login`，扫一下自动保存 Cookie，不用手填 |
| 图片模式 | 把动态渲染成长图（第三方截图站，可关，失败自动退纯文本） |
| 夜间勿扰 | 勿扰期间只更新状态不发消息，避免早上刷屏 |
| 自定义模板 | 7 个模板，占位符见下 |
| 仪表盘 | 增删订阅、改房间号、按 UP 配群、测试推送、立即检查 |

## 安装

要求 **AstrBot >= 4.0**（仪表盘需要支持 `views/` 插件页面的版本）。依赖只有 `aiohttp`（AstrBot 自带）和 `qrcode`（生成登录二维码，纯 Python，插件目录里的 `requirements.txt` 会在安装时自动装）。

**方式一：WebUI 上传**

插件 → 安装插件 → 本地上传，选打包好的 zip。

**方式二：git clone**

```bash
cd AstrBot/data/plugins
git clone https://github.com/HyperTide-Plugin/astrbot_plugin_bili_monitor.git
```

**方式三：手动复制**

把整个仓库目录放进 `AstrBot/data/plugins/astrbot_plugin_bili_monitor/`，保证 `metadata.yaml` 位于该目录下。

装好在插件列表点「重载」。

## 配置

四个列表 + 一个开关：



**推送隔离**（重点）：

- ④ 里同一个 UID 可以写多行，就推多个群；每个 UP 只发自己名下的群，**永远不会串到别人的群**
- 「严格隔离」默认开启：没在 ④ 里配群的 UP 主**不推送**，避免误发到默认群里
- 关掉「严格隔离」后，那些没配专属群的 UP 主才会回落到 ③ 默认推送
- 最省事的做法是打开仪表盘，点每个 UP 主那行的「推送」按钮，直接加群

- **② 留空自动获取**：走 `room/v1/Room/getRoomInfoOld`，兜底读 `acc/info` 的 `live_room`。填了就以手填的为准。
- **会话 ID 不知道填什么**？在目标群里发 `/bili id`。
- 房间号缓存失效（直播接口报错）会自动重新解析，不用手动删状态。

## 扫码登录（自动拿 Cookie）

不用去浏览器复制 Cookie ，两种方式：

- **仪表盘**：③ 运行参数 → 「扫码登录 B 站」→ 屏幕出二维码 → 手机 B 站扫 → 点确认。成功后 Cookie 自动保存并立刻生效。
- **聊天指令**：在群里发 `/bili login`，机器人把二维码发到聊天里，扫完会自动回复「登录成功」。

状态会实时变：`等待扫码…` → `已扫码，请在手机上点确认` → `登录成功，Cookie 已保存`。
二维码 3 分钟过期，过期后重新点一次即可。

### 用谁的账号？只用来拿 Cookie

这是最容易踩坑的地方，说清楚：

- **扫码的是哪个 B 站账号，机器人以后就用哪个账号的身份**。谁扫这个码，绑的就是谁的号。
- **扫码仅用于获取 Cookie**，让插件带登录态去读公开接口（动态、直播、用户信息），降低风控概率。
  插件**不会**发布、点赞、关注、投币、修改资料，代码里也没有任何写接口调用。
- **建议用小号**，别用主号。万一被风控，影响只落在小号上；主号也能用，但风险自负。
- **默认只有管理员能触发**（配置项 `admin_only_login`）。否则群里任何人都能发 `/bili login`，
  把自己的号绑到机器人身上——那之后机器人就是"他"的身份了。
- **随时可以解绑**：B 站 App → 我的 → 设置 → 登录设备管理，移除对应设备；
  或者把插件配置里的 `cookie` 清空。两者互不影响。
- 仪表盘会显示**当前登录的是谁**（昵称 + UID），换号、失效一眼能看出来。
- Cookie 是登录凭证，等同于密码：配置文件别外传，也别提交到 git（仓库的 `.gitignore` 已排除 `data/`）。

保存的是 `SESSDATA`、`bili_jct`、`DedeUserID` 这几个关键 Cookie（写入插件配置的 `cookie` 项，只写不读，仪表盘里看不到原文）。

> 二维码是本地生成的（`qrcode` 库出矩阵 + 自己写 PNG），不会把你的登录二维码发给任何第三方。
> 如果服务器上装不上 `qrcode`，插件不会崩，会自动降级"把登录链接发给你手动打开"。

## 指令

| 指令 | 作用 |
|---|---|
| `/bili list` | 已订阅的 UP 主、房间号、上次检查、是否在直播 |
| `/bili info <UID>` | 查昵称、粉丝数、最新动态、直播状态 |

| `/bili id` | 回显当前会话 ID |
| `/bili help` | 帮助 |

指令只读，不修改订阅关系——加删 UP 主请在配置或仪表盘里做。

## 仪表盘

插件详情页里的可视化视图（`views/dashboard`）：

- **状态**：运行中/已停止、订阅数、已配专属群数、正在直播数、轮询间隔
- **① 订阅 UP 主**：UID 回车即加；每行显示昵称、房间号、推送群数、上次检查、直播中；「推送」按钮单独管这个 UP 主的群（支持多个），「房间号」按钮单独改房间
- **② 默认推送**：只在关闭严格隔离时作为兜底；有 UP 主没配群时页面顶部会出现一键复制横幅
- **③ 运行参数**：启停、开播提醒、图片模式、严格隔离、间隔、勿扰时段、Cookie、代理、扫码登录
- **底部**：保存（`Ctrl+S` 同效）、立即检查（真拉接口，有新动态也推）

页面通过 `window.AstrBotPluginView` 调后端 `/astrbot_plugin_bili_monitor/*`，bridge 不可用时退回同源 `fetch`。老版本 AstrBot 不支持插件页面时仪表盘打不开，但插件与配置表单照常可用。

## 模板占位符

| 占位符 | 含义 |
|---|---|
| `{nick}` | UP 主昵称 |
| `{uid}` | UP 主 UID |
| `{text}` | 动态正文（超长截断到 500 字） |

| `{link}` | 跳转链接 |
| `{time}` | 发布时间 `MM-DD HH:MM` |

占位符没值当空串；模板里有落单的 `{` 也不会崩，会原样发出。

## 风控与 Cookie

B 站对匿名请求查得紧，插件做了这几层处理：

1. 自动获取匿名 `buvid3` / `buvid4`
2. 用 `web-interface/view` 预热指纹
3. 动态接口自动 WBI 签名（`w_rid` + `wts`），并带正确的 `Referer`
4. 带浏览器级请求头（`Sec-Ch-Ua` / `Sec-Fetch-*`）和 `b_nut`、`_uuid`、`b_lsid` 这些网页端必带 cookie
5. 遇到 `code=0` 但 `items` 为空（软反爬）交替两套参数重试 4 次
6. 遇到 `412 / 429 / 403` 立即冷却（默认 300 秒），冷却期内不再发请求——越打只会封越久

### 遇到 412 `request was banned`

这是 B 站 WAF 在 **IP 层**拦的，不是签名或参数问题，机房 / 云服务器 IP 特别常见（家宽一般不会）。按下面顺序处理：

| 步骤 | 做法 | 说明 |
|---|---|---|
| 1 | 用仪表盘或 `/bili login` 扫码登录 | 请求挂到真实账号上，能过大部分 WAF |
| 2 | 配置里填 `proxy` | 换成住宅/家宽出口，最有效；支持 `http://user:pass@host:port` |
| 3 | 把 `check_interval` 调到 180 以上 | 降低频率，缓解限流型 412 |

配置项 `risk_cooldown` 控制冷却时长（默认 300 秒，可调到 600–1800）。冷却期间日志只在每 10 分钟提示一次，不会刷屏。

常见错误码：`-352` 风控/签名问题；`412` WAF 拦 IP；`-799`、`429` 请求过密。

## 目录结构

```
astrbot_plugin_bili_monitor/
├── main.py            轮询、去重、推送、指令、仪表盘接口、扫码登录
├── bili_api.py        B 站接口 + WBI 签名 + buvid + 空结果重试 + 扫码登录
├── parser.py          动态卡片解析（各种 major 结构归一化）
├── qr.py              二维码 PNG（qrcode 出矩阵，zlib 自己拼 PNG）
├── metadata.yaml      插件元信息
├── _conf_schema.json  配置面板定义
├── requirements.txt   只有 qrcode
├── logo.png           插件图标
├── views/dashboard/   仪表盘（index.html / app.js / style.css）
└── tests/             本地测试与 astrbot 桩
```

运行状态（已推送的动态 ID、直播间号、开播时间、人气峰值）存在
`data/plugin_data/astrbot_plugin_bili_monitor/state.json`。

## 常见问题

| 现象 | 处理 |
|---|---|
| 有更新但没推送 | 这个 UP 没配专属群，且开着严格隔离；点该行「推送」加群 |
| 一直没动静 | `enable` 关了、UID 列表为空、或间隔太大 |
| 消息发到了别人的群 | 检查 ④ 里这个 UID 有没有误配；严格隔离下不会串 |
| 房间号一直空 | 该 UP 主没开通过直播间；或手动填一个 |
| 图片发不出来 | 截图站不可用，已自动退纯文本 |
| 日志反复 412 | 机房 IP 被 WAF 拦：先用扫码登录拿 Cookie，仍不行就配 `proxy` |
| 扫码后一直「等待扫码」 | 确认扫的是插件显示的那张码；3 分钟会过期，重新点一次 |
| 扫码成功但 Cookie 没生效 | 看日志有没有「扫码登录成功」；没有就重载插件再试 |
| 第一次启用就刷屏 | 调小「首次运行只推最近多少小时」 |
